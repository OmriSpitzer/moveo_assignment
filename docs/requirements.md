# Requirements

## Requirements

- [x] Answer hub questions using public weather and hazard APIs
- [x] Rank and compare hubs with an explicit KPI in code
- [ ] Explain the reasoning in plain language
- [ ] State assumptions, uncertainty, and what is out of scope
- [ ] Keep conversational follow-ups in one session
- [x] Chat UI talks to the agent only through the API
- [x] Validate model output against a JSON schema before code uses it
- [ ] Include a small evaluation set and a way to run it

Bonus, only after every item above is done:

- [ ] Voice input
- [ ] Scheduled or webhook alert when a hub's risk score changes
- [ ] Deployed URL

### Current status (Done, Work on, Not implemented)


| Requirement                     | Status                                                                                                                                                                                          |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public weather and hazard APIs  | Done. `get_weather_history`, `get_disaster_history`, and `get_active_alerts` call Open-Meteo, FEMA, and NWS. All 14 hubs now have seed coordinates                                              |
| KPI in code                     | Done. `score_hubs` calls `score_hub` and returns hubs highest score first. The score is stored on the hub with `scored_at` and recalculated when it is older than one day |
| Plain-language reasoning        | Work on. The prompt asks for one or two sentences, a bullet only for a new fact, and no repeated zeros. Not checked live                                                                        |
| Assumptions, uncertainty, scope | Work on. A technology question is out of scope. The model answers it itself, without tools or tool names, and stays on hub weather risk. Not checked live |
| Follow-ups in one session       | Work on. The Ollama agent stores the thread in memory, keyed by `thread_id`, and a later turn adds only the new message. A unit test covers that. A live follow-up was not run |
| UI only through the API         | Done. The chat calls only `/api/hubs` and `/api/agent/stream`                                                                                                                                   |
| JSON schema validation          | Done. The model reply is accepted as `LLMAnswer` (`answer` only); plain text from the model node is validated the same way. The call-limit message stays an error                               |
| Eval set                        | Not implemented                                                                                                                                                                                 |
